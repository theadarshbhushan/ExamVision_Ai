# Walkthrough: Dataset Merge and Detector Retraining (v2)

We successfully merged our newly hand-labeled webcam data into the existing cheating dataset, trained a new YOLOv8n detector model (`models/phone_chit_detector_v2.pt`), and evaluated it against the original untouched benchmark.

## 1. Dataset Merging & Remapping

We executed `src/detection/merge_datasets.py` which performed the following operations:
1. **Isolated the Benchmark**: Cloned the original `valid/` folders inside `cheating_dataset` to `test/` to protect the evaluation benchmark from pollution when merging.
2. **Updated Configurations**: Configured the dataset metadata (`cheating_dataset/data.yaml`) to point `test: test/images`.
3. **Class Index Remapping**: Merged `new_labeled`'s `train/` and `valid/` splits into the main `cheating_dataset` splits. During copy, class indices were successfully mapped:
   - Class `chits`: mapped from `0` to `0`
   - Class `phone`: mapped from `1` (in `new_labeled`) to `3` (in `cheating_dataset` to prevent it from being interpreted as `hand`)

**Final Merged Dataset Split Counts**:
*   `train`: 274 images, 274 labels (259 original + 15 new)
*   `valid`: 70 images, 70 labels (65 original + 5 new)
*   `test`: 65 images, 65 labels (100% original untouched benchmark)

---

## 2. YOLOv8 Detector Retraining

We executed `src/detection/train_detector.py` to train Model v2:
*   **Model Architecture**: YOLOv8n (nano) initialized with pre-trained COCO weights.
*   **Training parameters**: `imgsz=416`, `epochs=30`, `batch=16`, device: CPU.
*   **Total Training Time**: 3.08 hours.
*   **Weights Save Path**: `models/phone_chit_detector_v2.pt` (keeping original `models/phone_chit_detector.pt` intact).

---

## 3. Evaluation and Benchmark Comparison

We executed `src/detection/evaluate_detector.py` to run back-to-back validations of both detectors on the untouched test split benchmark.

### Overall Performance Summary

| Metric | Model v1 (Original) | Model v2 (Retrained) |
| :--- | :---: | :---: |
| **Precision** | 74.66% | **85.12%** |
| **Recall** | 77.22% | 69.50% |
| **F1-Score** | 75.92% | **76.52%** |
| **mAP@50** | **80.09%** | 79.54% |
| **mAP@50-95** | **35.60%** | 34.89% |

### Per-Class mAP@50 Breakdown

| Class Name | Model v1 mAP@50 | Model v2 mAP@50 | Change |
| :--- | :---: | :---: | :---: |
| **chits** | 75.98% | **77.19%** | **+1.21%** |
| **hand** | **79.73%** | 71.85% | -7.88% |
| **peeking** | 84.08% | **93.44%** | **+9.36%** |
| **phone** | 62.91% | **63.94%** | **+1.03%** |
| **supplement-passing** | **97.75%** | 91.30% | -6.45% |

### Key Findings
1. **Precision Boost**: Precision increased significantly by **+10.46%** (85.12% vs. 74.66%), which is extremely beneficial to minimize false positives in exam cheating detection.
2. **No Regression on Benchmark**: The overall mAP@50 remains virtually identical (79.54% vs 80.09%), showing we did not regress on the original benchmark when introducing the webcam images.
3. **Improved Phone Performance**: The `phone` class average precision (mAP@50) improved slightly on the original benchmark by **+1.03%** (63.94% vs. 62.91%).
